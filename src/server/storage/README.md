# Local SQLite storage

`createStorage({path,now,encryptionKey,keyVersion,maxBytes})` returns `repository`, `sessions`, `budget`, and a separate `tokenVault` for the auth adapter only. `now` returns UTC epoch milliseconds. Timeline ranges remain session-relative milliseconds. The SQLite file has a default 2 GiB page cap; `maxBytes` can lower it. Runtime must hold its single-instance lock before opening the file. Every method is synchronous; awaiting a method is supported, but no callback may do network IO inside a transaction.

The live engine commits through `applyDomainTransition(scope,sessionId,{expectedRevision,expectedPrivacyEpoch,transition,event,idempotencyKey?,requestBody?,expectedEntity?,settingsPatch?})`. It accepts the canonical pure-core `DomainTransition`, preserving its entity/candidate IDs. The reducer runs before the SQLite transaction. The transaction checks the revision, epoch and optional editorial fence, then saves the event, sources, graph, candidates, session/settings, checkpoint and durable effects together. Existing event receipts return a duplicate result before checking stale revisions; reusing a mutation key with different request content conflicts. `getDomainMutation` returns a compact receipt without historical private text. Runtime should use the returned authoritative checkpoint or reload hydration after committing. The low-level `commitStory` API remains for adapter-level contracts and is not a second live generation pipeline.

`getDomainCheckpoint` returns `{revision,privacyEpoch,checkpoint}`. `getDomainHydration` adds current session/settings, up to 500 sources, bounded canonical entities/candidates, text-free historical leaf metadata, tombstones, channel blocks/bans, safe blocked-lore control stubs, capture epoch and chat-clear cutoff. Source selection reserves up to 64 recent non-chat records within the 90-second evidence horizon, then fills the remaining slots with newest sources; it selects IDs before hydrating raw text. Equal timestamps use the same UTF-8 binary ID order as the core. Private checkpoints are capped at 16 MiB; they are not public DTOs or replay exports. Standalone privacy destroys affected checkpoint bodies; recovery rebuilds only surviving authoritative records. Metadata deletion clears materialized title/category and fences old observations. Range matching uses the exact pure-core overlap rule: positive-duration ranges overlap strictly; point events include endpoints.

`listPendingDomainEvents(scope,sessionId,limit)` caps recovery batches at 100 and returns `{event,sources}`. This lets already-accepted audio survive a restart before its domain callback; events become processed in the domain transaction. Raw provider-result events participate in dependency invalidation. A late result with a stale ticket is retained only as an ID/type/timestamp record, never with rejected private text.

Effect mapping: generation requests create `jobs.kind='story'` with `{request}`; owner checks create `owner.review` jobs with IDs, revisions, epoch and refs; clips create `twitch.clip.intent` jobs with `{moment,privacyEpoch}` for the Twitch adapter to convert into its typed outbox. Owner-review IDs include privacy epoch, allowing surviving held edits to be rechecked after a privacy fence. Publications create one final `publish`/priority `retract` outbox per transition, with `{snapshot,final,affectedSessionIds,affectedIds}`. Playback outbox payloads are `{action,playback}`. `pendingJobCount`, `getActiveSession`, `listOpenSessions`, and `cancelSessionEffects` support shutdown/drain without scanning archived history. Cancelling an already-running chat/clip/marker records an unknown outcome.

`controlGet/Put/Delete/Take/Claim/Update` provide scoped control persistence with optional expiration, 256-character keys and 32 KiB values. `take`, `claim` and `update` are atomic. `runIdempotentControl` wraps a synchronous control mutation and its compact result in one transaction, used for stable capture anchors on transport retries. Provider credential fields are rejected; use `tokenVault` instead. `getSettings` and `updateSettings` use the shared schema and optimistic revision checks, with optional idempotency for settings changes before a stream exists. Nested storage helpers use SQLite savepoints; asynchronous callbacks are rejected.

The database uses DELETE journaling, foreign keys, and secure deletion. Back up the SQLite file **only after stopping the instance**; restore the matching environment encryption key separately. Losing or replacing that key does not reset saved credentials: opening the vault fails with `key_setup`.

`ensureChannel` / `createSession` establish scope. `ingest(event,{sources,jobs,outbox})` saves evidence and effects in one deduplicated transaction. All IDs, reads, leases, and edits require the same channel/run scope. `saveEntity` stores typed domain records in the normalized `entities` table: claims, relations, chapters, current state, presentations, lore, moments, media, playbacks, provider caches, and exports share dependency invalidation. Entity IDs and source IDs must share one namespace. A media record must supply its conservative capture start/end range.

`getSession` returns the shared Session DTO. `updateSession` saves metadata and monotonic live → closing → finalized lifecycle; finalization requires end/finalization times. `listSessions` caps pages at 50; `listSources` and `listEntities` cap pages at 500 and accept stable cursors. `isTermBlocked` and `listBlockedTerms` expose channel/run lore suppression; their session argument remains for compatibility. Terms normalize NFKC, case, and whitespace; blocking hides matching lore and its descendants in every session, preserves speech/chat mentions, and rejects later creation of that lore term. Migration 3 preserves earlier per-session blocks and invalidates previously permitted matching lore across sessions.

Before a provider call, `registerGeneration(ticket,entityId)` saves all exposed inputs. `commitStory` rejects stale epochs, source revisions, owner revisions, locks, and unsupported claims. Candidates are immutable and initially unsafe. `markCandidateSafe` requires both moderation and PII approval. `publishEligible` selects the newest matured safe candidate without waiting for a newer draft. Domain adapters remain responsible for strict shared schema validation, meaningful story decisions, and public DTO projection. The stored patch is not itself a public DTO.

If generation sees the previous version of its own chapter, commit preserves that context in an immutable dependency node. Later drafts do not invalidate that node; owner edits and privacy deletion still reach it. Privacy epoch changes invalidate obsolete pending candidates and free their bounded queue slots while retaining unaffected already-published pointers.

`invalidate(scope,target,{idempotencyKey,reason})` tombstones matching inputs, clears event bodies and all derived bodies, cancels in-flight work, revokes candidate pointers, and queues priority retract atomically. Reason text is hashed for idempotency but is not saved. Receipts contain IDs only. File unlink happens outside the transaction after media is hidden. `editEntity` preserves existing lineage, locks model overwrites, withdraws old candidates and dependent presentations, and queues retract. `registerOwnerCandidate` stages the reviewed owner revision without another time hold; explicit moderation/PII approval is still required before publication.

Whole-session Forget also clears entities with no dependencies, raw events without source records, and title/category metadata; it revokes capture and fences later arrivals. `pinEntity` uses the entity revision as an atomic write fence, increments the session publication revision and queues publication in the same transaction. Pinning preserves model wording permissions. Both generation registration and commit require the entity and ticket to belong to the same session.

Use `enqueueJob`/`claimJob`/`renewJob`/`finishJob` and matching outbox methods. The lease token changes each claim; an expired worker cannot finish a replacement worker's claim. `unknown_outcome` is terminal until an explicit owner resolution; do not supply `nextAtMs` for an ambiguous network effect. Expired chat/clip/marker outbox leases become ambiguous, never automatically resent. `publishEligible` atomically queues a publication reference; `preparePublication` assigns a persistent sequence once for explicit snapshot bodies and a retry reuses it. A publisher must produce a fresh safe DTO after privacy invalidation, never relabel an old body. `recordRemoteArtifact` preserves cleanup-only clip IDs after a stale response.

`freezePublication` verifies the live worker lease, privacy epoch, SHA-256 and the 3.5 MB complete-wire-operation bound, then saves exact bytes once for retries. `getPublicationState` exposes channel sequence/privacy revision and ACK status. Privacy and priority editorial withdrawal cancel stale publication work and clear frozen bodies. A conflicting ACK hash for a known sequence is rejected.

`acceptAudio` atomically checks capture/epoch/privacy, source tombstones, monotonic sequence/nonoverlap and the three-pending-STT cap, then saves the chunk descriptor and job. Exact tuple/hash retries return the original IDs. `commitAudio` requires the current worker lease and unchanged capture/privacy epochs, saves checked speech and its recoverable `speech.transcribed` event, and completes the job atomically. A live commit also requires an unexpired capture lease. Already-accepted closing results retain their separate 90-second tail boundary; pause or takeover still fences them. Raw-file unlink and bounded filesystem cleanup belong to the audio adapter, outside SQLite.

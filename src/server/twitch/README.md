# Twitch adapter integration

`createTwitchAuth` from `../auth/index.ts` returns the `AuthenticationPort`, absolute-path auth router, relative owner router, token lifecycle, and start/stop/status. Supply a numeric channel scope resolved with `resolveConfiguredChannel` only after a login is configured. `bindControlStore(repository, scope)` binds SQLite controls. Only auth receives the encrypted vault. Start validates a persisted token and starts hourly checks. `onAuthorized` starts the integration after callback; `onDisconnect` stops EventSub promptly. Auth success never marks stream or microphone live. Marker scope is opt-in via `markerEnabled`.

Mount `router` in the application's auth router registry before overlay guards. Mount `ownerRouter` beneath `/api/owner` after owner/CSRF/idempotency guards. Routes: `/api/auth/twitch/start`, `/auth/twitch/callback`, `/api/auth/logout`, `/api/overlay/session`; owner `/twitch/status`, `/twitch/disconnect`, `/overlay-key`. `POST /overlay-key` creates the first capability; replacing it requires `{rotate:true}`. Only its hash is saved, so an existing raw URL cannot be recovered. The response URL is shown once. The overlay exchanges its fragment in the POST body, removes the fragment, and receives a separate cookie and CSRF token. Owner logout leaves overlay access intact; rotate revokes overlay sessions, and `onOverlayRotated` must close existing SSE connections.

`TwitchEventSub` consumes `TwitchHelix`, durable controls, and injected `ingest`, `resolveSession`, `onStream`, ban synchronization and status ports. The root owns stream identity, normalized envelope ingestion, reducer persistence, publication, and effect scheduling. Map Twitch payload fields to domain events there. `onStream` must be idempotent for stream ID plus startedAt; null means confirmed offline (optional third argument identifies the old stream). A delayed offline without an ID is ignored if Get Streams reports live. The root closes only the identified episode and cancels new old-episode chat/clip work. It must keep tail processing and final ACK independent.

`TwitchBanSync` supplies EventSub's `bans` port. Route normalized `channel.ban`/`channel.unban` through `ban()`/`unban()`. Its `onBlocked(actor, throughAt, reason)` callback invalidates matching persisted actor sources and their derivatives across sessions; unban never removes tombstones. Use `allows(actor)` in final safety checks. Call `suspend()` whenever EventSub status is gap/revoked/disconnected, and start/stop its bounded expiry checker with the integration. Snapshot pages are durable, newer moderation events win, and expired/uncertain restrictions stay blocked until a point query confirms removal. `verifyActor` is available for an explicitly encountered restricted actor.

`TwitchEffects` writes chat/clip/marker outbox work and clip-poll jobs into the shared repository. Call `tick()` from the root scheduler. `allowed(context)` is a synchronous final fence for session/live status, privacy epoch, dependencies, published content, actor restrictions, and paused automation. It runs again immediately before HTTP, including after token refresh and a 401 retry. Chat commands use `parseCommand` and `composeReply` from safe public snapshots. Pass `isOwnEcho(message_id)` before command processing; do not discard human messages from the broadcaster by actor ID. Raid welcome uses the same `enqueueChat` business-key dispatcher. Mock/replay envelopes must never reach this live sink.

Clip creation happens immediately when enabled, not after the publication hold. Setup must explain the external public clip boundary before enabling auto clips. Supply a conservative capture interval (at least the possible 85 seconds before and 5 seconds after the request, clipped to session start). A successful create only sets pending; `onClip` receives ready after metadata and authorized media preparation. The media callback must use the private cache, its own privacy gate, HTTPS host validation, 80 MB cap and ffprobe. Keep the conservative interval until exact source alignment is verified. Returned late clip IDs are recorded in cleanup-only outbox metadata; Twitch has no documented public Delete Clips endpoint. Owner cleanup URL is `https://dashboard.twitch.tv/content/clips`.

At connect/startup call `previousCandidate(currentStartedAt)` to sample up to 100 metadata records from the last 30 days. Twitch returns clips by popularity; the adapter explicitly sorts the bounded permitted sample by creation time. `previousPermitted` must exclude rejected/forgotten clips. Expose the candidate for Preview/Use; `preparePrevious` downloads it before raid playback and marks it as previous-session. Do not treat that clip as current-stream evidence. Its context must retain the original capture interval and privacy lineage.

The installed official Twitch CLI 1.1.24 delivered real mock WebSocket payloads for raid, ban, unban, channel.update v2, online and offline; graceful reconnect preserved subscriptions. Run `TWITCH_CLI_PATH=<installed executable> npx vitest run tests/twitch/cli.test.ts` (set the variable using the current shell). The test checks that CLI's fixed RPC port 44747 is free, selects an ephemeral WS port, spawns hidden on Windows and stops its own process. This CLI version rejects the four newer `channel.chat.*` subscriptions and cannot trigger them; only those four mock subscriptions are stubbed. Their behavior is fixture-tested, not CLI- or live-proven. CLI offline also predates the newer stream ID field; the adapter explicitly covers both shapes.

Still required with the user's channel: real OAuth/scopes/refresh, all ten production subscriptions, second-account chat/moderation/raid, network recovery, actual own clip download and measured source alignment/playback. No account authorization, live network call, chat send or clip creation was attempted here.

Official contracts checked: [token validation](https://dev.twitch.tv/docs/authentication/validate-tokens/), [WebSocket lifecycle](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/), [Helix clips and downloads](https://dev.twitch.tv/docs/api/reference/#get-clips-download), [chat send limit](https://dev.twitch.tv/docs/api/reference/#send-chat-message).
